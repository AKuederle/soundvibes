# phonon2

Rust abstraction for the original Fermion Research Phonon-2 model. Uses the native
CPU encoder and TDT decoder shipped in `fermion-research==0.2.6`. Loading, audio
features, encoder projection and vocabulary decoding run in Rust. No Python,
PyTorch, Transformers, ONNX Runtime or network access is needed for inference.

```rust,no_run
use std::path::Path;
use phonon2::Model;

let mut model = Model::load(Path::new("/path/to/phonon2"), Path::new("/path/to/phonon2/native"))?;
let audio = vec![0.0f32; 16_000]; // mono PCM at 16 kHz
let text = model.transcribe(&audio)?;
# Ok::<(), phonon2::Error>(())
```

Prepare assets once from the repository root. Setup requires Python 3.11+ and
zstandard; `uv` can supply that dependency without installing the inference package:

```sh
uv run --with zstandard python scripts/prepare-phonon2.py
```

The default directory is `$XDG_DATA_HOME/soundvibes/models/phonon2`, or
`~/.local/share/soundvibes/models/phonon2`. Override it with `--directory`.
Downloads are pinned to model revision `8ec0e26676d2d57149280e72dbeca922d482b61c`
and Python package version 0.2.6. The setup script verifies archive/container and
wheel SHA256 values. The crate independently verifies each selected library's
SHA256 and ABI 1 before creating native handles. The crate expects the unpacked
archive's runtime `config.json`, not the Hub's top-level descriptor.

Supported hosts are Linux x86_64 with SSE4.1 and Linux aarch64 with NEON. Selects
the baseline binaries on older CPUs and the optimized binaries when supported.
The Arm path is implemented but has not been exercised on real Arm hardware.
The initial integration uses the official default one-dot CPU mode, which
approximates five-value weights with per-row int8 execution tables. It preserves
the Phonon-2 model; arithmetic differs from the dense FP32 reference. There is no
GPU path or dense fallback in this crate.

Input must be finite mono f32 PCM at 16 kHz. Phonon-2 is English only. Decoding is
greedy TDT, without language selection or hotword bias. Long audio is split into
consecutive 35-second windows; Soundvibes' pause-based segmentation is preferable
for avoiding word cuts. Audio shorter than 10 ms returns empty text. A model may
move between threads, but calls across models are serialized because upstream
native libraries share global thread pools.
Libraries remain loaded for the process lifetime so their worker threads cannot
execute unloaded code. Thread pools are initialized once; model weights and
handles are released when each model is dropped.

Run the standalone WAV example and real-model test:

```sh
cargo run --release -p phonon2 --example transcribe -- MODEL_DIR MODEL_DIR/native vendor/whisper.cpp/samples/jfk.wav
PHONON2_MODEL_DIR=MODEL_DIR PHONON2_LIBRARY_DIR=MODEL_DIR/native cargo test -p phonon2 --release -- --nocapture
```

Without environment variables the real-model test skips. If assets are explicitly
configured, missing or invalid files fail the test. The small committed front-end
fixture is generated by the official 0.2.6 CPU implementation from the first 200 ms
of the bundled JFK audio. Both the short WAV and its feature oracle are committed,
so this test requires no model files or whisper.cpp checkout.

To reproduce the Python comparison, install CPU PyTorch, `transformers==5.17.0`,
`fermion-research==0.2.6`, soundfile and scipy in a separate environment, then run:

```sh
python scripts/phonon2-reference.py MODEL_DIR vendor/whisper.cpp/samples/jfk.wav reference.json
PHONON2_MODEL_DIR=MODEL_DIR PHONON2_LIBRARY_DIR=MODEL_DIR/native PHONON2_REFERENCE_JSON=reference.json PHONON2_REFERENCE_FEATURES=reference.f32 cargo test -p phonon2 --release -- --nocapture
```

The reference script also saves time-major FP32 features alongside its JSON.
The comparison requires matching words and checks every feature within 0.0003.
Punctuation and capitalization may differ between numerical implementations.

Native ABI definitions and weight decoding are based on the Apache-2.0 Python
sources in fermion-research 0.2.6. Those native binaries are external artifacts;
their C sources and public headers were absent from the inspected distribution
and upstream repository. Upgrades require deliberate ABI and numerical checks.
Model weights are CC-BY-4.0, derived from NVIDIA Parakeet TDT 0.6B v3. The setup
script retains upstream code and model notices. See NOTICE and the repository LICENSE.

The setup regression test reruns preparation while a native library is mapped.
It requires Python with zstandard and cached prepared assets:

```sh
PHONON2_MODEL_DIR=MODEL_DIR PHONON2_MODEL_ARCHIVE=/path/to/phonon-2.bps.tar.zst cargo test -p phonon2 --test setup
```

Use `PHONON2_SETUP_PYTHON` to select a Python environment. Cached assets are used
without network access. Library updates replace files atomically so an active
inference process keeps its original mapped code.
